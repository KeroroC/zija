# 阶段七不交付性能验证

spec §13 给出明确的规模目标（20 成员 / 20,000 物品 / 100,000 批次 / 1,000,000 流水）与 P95 延迟目标（普通列表/详情 < 500 ms，首页 < 1 s），交付路线图把「性能检查」列为阶段七必达结果之一。

决定：阶段七不交付通用业务性能验证——不引入 `make perf-smoke`、不新增业务规模种子器、不进 CI。
但 AI Embedding 模型切换允许一个独立的本地手动基准例外：使用固定的中文检索样本对比模型效果、
峰值内存和 P95 生成延迟，产出本地报告，不作为全系统性能承诺。

理由：通用性能验证的真正价值在「真实规模 + 真实硬件」下度量，单家庭私有部署的目标硬件差异大（NAS /
家庭服务器 / 云主机），CI 上的容器化基准不能代表用户体验；而 1,000,000 流水的种子机制本身又得选型，
会制造与当前阶段无关的工程投入。Embedding 基准只回答本次模型选择的相对问题，样本规模小、手动执行、
不进入发布门禁，和通用业务压测的风险不同。
