# 阶段七不交付性能验证

spec §13 给出明确的规模目标（20 成员 / 20,000 物品 / 100,000 批次 / 1,000,000 流水）与 P95 延迟目标（普通列表/详情 < 500 ms，首页 < 1 s），交付路线图把「性能检查」列为阶段七必达结果之一。

决定：阶段七不交付任何性能验证——不引入 `make perf-smoke`、不新增种子器、不进 CI、不产报告。性能验证整体延后。

理由：性能验证的真正价值在「真实规模 + 真实硬件」下度量，单家庭私有部署的目标硬件差异大（NAS / 家庭服务器 / 云主机），CI 上的容器化基准不能代表用户真实体验；而 1,000,000 流水的种子机制本身又得选型（应用内 seeder / 直 SQL / 压测客户端），均为阶段七之外才有结论的工程投入。当前阶段优先把发布、备份、恢复、文档这些「能安装能恢复」的硬门槛交付到位，性能验证留到有真实部署反馈后再设计。伪造规模的 CI 性能门只会制造虚假信心。
