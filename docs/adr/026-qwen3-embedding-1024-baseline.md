# ADR-026: qwen3-embedding 1024 维作为开发基线

状态：已批准。

## 背景

知家当前使用 Ollama `nomic-embed-text:latest` 生成 768 维知识向量。中文家庭附件是首期知识问答的
主要输入，当前模型基线需要在中文召回和本地资源占用之间重新取平衡。向量表、运行时探活、实际写入
校验、测试假模型和部署示例都把维度写成了 768，模型切换不能只改一个环境变量。

## 决策

- 默认 embedding 模型改为 `qwen3-embedding:0.6b`。
- 1024 是全局嵌入维度契约。所有可配置 embedding 模型都必须返回 1024 维；探活或实际写入发现其他
  维度时，AI 知识能力报告 `EMBEDDING_DIMENSION_MISMATCH`，不静默回退到旧模型。
- 知识向量直接重建，不维护 768/1024 双索引。开发基线直接修改 Flyway 的 `V10` 建表语句为
  `vector(1024)`；已有个人开发数据库按新基线重建，不设计旧版本兼容或回滚流程。
- 知识来源选择是用户意图，必须保留。基线重建时，所有非 `DISABLED` 来源重置为 `PROCESSING`，清空
  失败信息、处理时间和重试计数，递增处理版本并立即进入现有异步准备队列；`DISABLED` 来源保持停用。
- 不可用或维度不匹配时不回退到 `nomic-embed-text`，核心业务仍可用，知识来源按现有失败与重试状态展示。

## 取舍

1024 维向量增加存储和计算量，但 `qwen3-embedding:0.6b` 以较小模型规模提供更适合中文的语义表示。
双索引或按模型动态选择维度可以保留旧数据，却会增加检索分支、资源占用和状态一致性风险；开发阶段没有
为此付出复杂度的必要。

## 验证

仓库提供本地手动 Embedding 基准脚本，使用人工编写的中文家庭库存与附件样本，对比
`nomic-embed-text:latest` 和 `qwen3-embedding:0.6b`：

- `Recall@5` 不低于 Nomic；
- 峰值内存和 P95 生成延迟不超过 Nomic 的 2 倍；
- 报告记录模型、硬件和样本数量；
- 基准不进入 CI，也不构成全系统性能承诺。

通用业务性能验证仍遵循 ADR-008 的范围，Embedding 基准是针对本次模型选择的局部例外。
