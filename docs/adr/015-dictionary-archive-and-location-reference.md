# ADR-015: 字典归档与位置引用标记

## 状态

已批准

## 背景

知家的物品字典（分类、品牌、标签、单位）和位置树是全家共享的稳定数据。一旦被物品或库存引用，物理删除会导致历史链路断裂。spec §5.1 要求物品引用后只能归档，位置有子节点或库存时不能删除。如何在模块边界内管理这些生命周期？

## 决策

### 1. 归档制（不物理删除）

- 所有字典项（分类、品牌、单位、标签）和物品只允许 `ACTIVE` 与 `ARCHIVED` 之间切换，不提供物理删除。
- 归档项不出现在新建选择器中，但历史物品保留已有的归档字典项引用，并在详情/列表中显示原始名称。
- 服务端不允许将归档字典项新关联到物品。
- 若需复用名称，Owner/Admin 必须恢复原记录而非创建新 ID。

### 2. 名称规范化

- 字典名称在去除首尾空白、Unicode NFKC 规范化并用 `Locale.ROOT` 大小写折叠后写入 `name_normalized`。
- 名称在同一家庭内不可与已归档记录重复。

### 3. 单位精度锁定

- 单位一旦被任一物品使用，其 `decimal_scale`（0–6）不可修改。
- 只能归档旧单位并创建新单位。库存数量必须符合关联单位的 `decimal_scale`。

### 4. 位置树与引用标记

- 位置使用邻接表（`parent_id`），不把路径写死在行内。读取整棵树使用递归 CTE。
- 移动节点使用事务和递归祖先检查：目标父节点不能是节点自身或其后代。
- **`ever_referenced` 不可逆标记**：`inventory` 模块在首次创建库存位或引用位置的流水前，通过 `LocationApi.markReferenced(...)` 在同一事务内将 `ever_referenced` 置为 `true`。置为 `true` 后该状态不可回退。
- 位置物理删除条件：无子节点、`ever_referenced = false`、调用者提交的版本仍匹配。任一条件不满足则拒绝删除。
- `LocationApi.markReferenced` 是模块内部服务调用，不暴露为 HTTP 端点。

### 5. 文件引用计数

> 附件成为 `file` 模块的聚合之后，引用计数不再是文件活着的理由；删除进入回收站、保留期满再物理删除。见 [ADR-019](019-attachments-in-file-module.md)。下列条目描述的是封面槽位时期的生命周期，已被修正。

- `FileApi` 为调用方维护引用计数：关联封面时 `retain`，替换或移除封面时 `release`。
- 引用数降至零后，在事务提交后删除元数据和实际文件。
- 实际文件先写入同一存储卷内的临时文件，再原子移动到 UUID 生成的对象键。
- 数据库事务回滚时，事务同步回调删除本次新增的对象；替换旧封面时旧对象只能在成功提交后删除。
- `storage_key` 使用服务端 UUID 和检测过的扩展名生成，不使用原始文件名。
- `catalog_item.cover_file_id` 只保存 UUID，不建立跨模块 SQL 外键。

### 6. 模块边界

- `catalog` 只通过 `FileApi` 管理封面，不直接查询 `file` 的 Mapper 或表。
- `inventory` 只通过 `CatalogApi` 读取物品和验证状态，不直接访问 `catalog` 表。
- `location` 通过 `LocationApi` 的 `markReferenced` 维护引用事实，不反向耦合 `inventory`。

### 7. 组合外键保证家庭隔离

- 分类父子关系、物品字典关联、标签关联和位置父子关系的组合外键保证不会跨越家庭边界。
- 名称在家庭内不强制唯一（不同家庭可有同名分类）。

## 考虑过的备选

- **物理删除已引用字典项**：历史物品详情无法显示原始分类/品牌名称，审计链断裂。
- **位置用物化路径（`path` 列如 `/a/b/c`）**：移动子树需要批量更新所有后代路径，且路径字符串操作易出错。邻接表 + 递归 CTE 更安全。
- **文件物理路径暴露**：`storage_key` 出现在审计日志或 Problem Details 中是安全风险。UUID 键 + 元数据分离是标准做法。
- **跨模块 SQL 外键**：破坏模块边界（见 ADR-011），`ModularityTests` 不可见。

## 后果

- 历史链路始终可解释：归档物品保留所有字典引用和封面。
- 位置引用一旦标记不可逆，`inventory` 模块可安全假设引用过的位置不会被删除。
- 文件清理自动化：引用计数降至零即删除，无需手动 GC。附件模型下此条已被 ADR-019 的回收站 + 保留期取代。
- 代价是归档数据累积，但单家庭规模下不是问题。
