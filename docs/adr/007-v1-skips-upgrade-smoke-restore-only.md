# 阶段七不交付升级冒烟，仅交付备份恢复验证

知家 v1 是首个发布版本，不存在任何已发布的「先前版本」可作为升级起点；开发期迁移 V1–V6 不构成已发布基线。因此阶段七的「升级冒烟测试」在本阶段无真实起点，强行伪造一个先前版本只会给未来读者制造误导。

决定：v1 仅交付「从备份恢复到空环境 → Flyway 从 V1 跑到当前迁移基线 → 库存位与流水一致性检查通过」这一验证链。升级冒烟整体延后到 v1.1（届时才有真正的「先前已发布版本」）。Makefile 不保留 `upgrade-smoke` 占位目标——干净延后，避免任何人误以为 v1 已支持升级验证。届时重新设计升级冒烟入口与目标版本契约。

权衡依据：spec §11.3 与交付路线图把「升级冒烟」当作已满足前提，但它与「v1 是首个发布」的现实冲突；伪造先前版本无法回答「升级」的真实命题（schema 已变、数据已变、版本已变）。真实可观测的成功条件只有「空环境恢复后系统自洽」这一条，这也是发布门槛真正能保证的事。
