# 知家 AI 能力规格

- **状态：** 已确认，作为核心产品首期之后的 AI 能力阶段实现与验收基线
- **日期：** 2026-08-16
- **适用范围：** 家庭事实问答、知识来源问答
- **AI 能力首期形态：** 私有部署桌面 Web 中的统一只读问答入口

## 1. 目标

知家 AI 能力阶段首期解决两个问题：

1. 家庭成员可以用自然语言了解家庭中的物品、批次、库存位、流水、位置和提醒。
2. 家庭成员可以选定已有附件作为知识来源，询问物品或批次的使用、维护和注意事项。

AI 是核心业务的可选增强能力。未配置可用模型或 AI 暂时不可用时，库存、附件和其他既有流程必须继续工作。

## 2. AI 能力首期范围

### 2.1 家庭事实问答

可查询的家庭事实包括：

- 物品是否存在、所在位置和相关批次；
- 某物品或批次的当前数量及位置分布；
- 临期批次、低库存物品和提醒任务；
- 流水明细、数量变化原因和操作时间；
- 由多个来源组成的上述问题，但每类依据必须分别标示。

不包含成员隐私、审计日志和系统配置。

### 2.2 知识来源问答

知识来源由成员从已有附件中显式选定。首期处理可提取文字的：

- PDF（必须包含可提取文字）；
- Markdown、TXT；
- DOCX、XLSX、PPTX。

扫描版 PDF、JPEG、PNG、WebP、HEIC/HEIF 等图片内容在 AI 能力首期不进入有效知识来源，OCR 另行规划。附件上传能力本身仍沿用现有格式规则。

## 3. 领域边界

### 3.1 家庭问答

家庭问答是自然语言只读查询能力。它可以提供相关物品、批次、位置、流水或附件页面的跳转入口，但不能直接修改任何业务数据。

### 3.2 知识来源范围

知识来源的检索范围由附件挂载点决定：

| 挂载点 | 可检索范围 |
| --- | --- |
| 家庭 | 全家庭问题 |
| 物品 | 该物品及其批次 |
| 批次 | 该批次 |

所有活跃成员共享家庭现有附件权限，可以选择、查询和取消知识来源。知识来源不是附件类型，不改变附件的文件内容、挂载点或生命周期。

### 3.3 知识准备状态

知识来源采用异步准备，用户可见以下状态：

- **处理中**：尚未完成内容准备，不参与回答；
- **可用**：可以参与回答；
- **失败**：处理未完成，可查看原因并重试；
- **已停用**：当前不参与回答，通常由成员取消或附件生命周期触发。

上传成功不等于知识来源已经可用。

## 4. 统一问答体验

### 4.1 入口与范围

- 使用一个统一问答入口；
- 根据当前页面和问题内容推荐回答范围；
- 清楚显示实际使用的家庭事实和知识来源；
- 用户可以收窄或调整范围，但不需要每次提问前手动选择；
- 物品、批次或位置名称有歧义时，先展示候选供用户确认。

### 4.2 回答结构

每个回答由三层组成：

1. **自然语言摘要**：直接回答用户问题；
2. **结构化结果**：库存数量、位置列表、提醒列表等使用表格或列表展示；
3. **回答依据**：显示来源类别、数据时间、附件名称、挂载对象，以及页码、章节或可定位文本片段。

一条回答可以同时使用两类来源，但必须分别标记。家庭事实负责当前状态，知识来源负责其内容范围，二者冲突时分别展示并说明冲突。

### 4.3 无依据与歧义

- 没有可用知识来源时，不使用模型常识补写，不联网搜索；
- 家庭事实来源不可用或过期时，明确说明暂时无法确认；
- 无法确定用户所指物品、批次或位置时，先要求选择，不静默猜测；
- 不允许模型生成 SQL、绕过查询端口或自行推算跨页汇总。

## 5. 权限、隐私与模型提供方

### 5.1 权限

- 家庭事实遵循当前成员权限和当前家庭边界；
- 知识来源沿用现有附件的家庭级共享权限；
- 模型提供方、凭据、出网开关和资源限制由 Owner/Admin 管理；
- 普通成员不能按单次提问切换模型提供方。

### 5.2 本地优先

- 默认不向外部服务发送家庭内容；
- 管理员可以明确配置外部模型提供方；
- 未配置模型时，AI 不可用但核心业务不受影响；
- 外部调用只发送当前问题、必要的检索片段和最小元数据；
- 不发送完整附件、完整家庭数据集或历史对话；
- 外部提供方应关闭内容留存或使用最短可用留存策略，不得将家庭内容用于模型训练。

### 5.3 对话与审计

首期不在服务端保存对话历史，仅保留当前浏览器会话内容。家庭问答审计只记录最小元数据：成员、时间、请求标识、结果、模型提供方和回答依据数量；不记录问题、回答或完整上下文。

### 5.4 技术基座

- 使用 **Spring AI** 作为模型接入、`ChatClient`、工具调用、文档处理和 RAG 编排框架；Spring AI 类型只存在于 AI 能力模块内部，不跨现有业务模块边界泄漏。
- 使用 **PostgreSQL pgvector** 作为知识来源的向量存储，与现有 PostgreSQL 单体部署和备份体系保持一致，不引入独立向量数据库。
- 家庭事实通过 Spring AI 工具调用连接到受控的公共查询契约；附件知识通过 Spring AI 的文档检索能力连接到 `PgVectorStore`。
- 检索必须使用 `householdId`、挂载点类型、挂载 ID、附件 ID 和知识准备状态等元数据过滤，过滤条件由服务端生成，不能由模型自行放宽。
- 具体 LLM、embedding 模型和外部提供方仍保持可替换，不在本规格中锁定。

## 6. 生命周期与可靠性

| 事件 | 知识来源行为 |
| --- | --- |
| 显式选定附件 | 进入处理中 |
| 处理成功 | 变为可用 |
| 处理失败 | 变为失败，允许有限自动重试和手动重试 |
| 取消选定 | 变为已停用，不参与检索 |
| 附件回收 | 立即停用，不论文件是否仍可下载 |
| 附件恢复 | 重新进入处理中，不自动恢复旧索引 |
| 附件改挂 | 按新挂载点改变检索范围 |
| 附件改名 | 只更新回答依据中的展示信息 |
| 附件永久删除 | 清除抽取文本、分块和索引等派生知识数据 |

模型不可用时：

- 家庭事实问题可以展示受控查询结果或明确失败原因；
- 知识来源问题停止生成，提示资料暂不可用并提供附件入口；
- 不以模型常识、联网搜索或猜测补答。

AI 请求需要具备成员级和部署级资源限制，包括请求频率、单次上下文大小、处理并发和超时；限制和失败原因对管理员可见。

附件中的文本始终是不可信资料。它只能被引用、总结和比较，不能改变 AI 的规则、权限或工具调用行为。

## 7. 备份与恢复

备份包含：

- 原始附件；
- 知识来源选择；
- 必要的 AI 配置。

抽取文本、分块和向量索引属于可重建的派生知识数据，不要求备份绑定某个模型或索引格式。恢复后按当前可用能力重新准备知识来源；在准备完成前，界面展示对应状态。

## 8. AI 能力首期明确不做

- 任何库存、物品、提醒或附件写入操作；
- 成员隐私、审计日志和系统配置问答；
- 扫描件和图片 OCR；
- 通用知识补答、联网搜索和厂商资料自动抓取；
- 服务端长期对话历史；
- 用户按问题切换模型提供方；
- 把知识来源内容当作系统指令；
- 将模型特定的派生索引作为备份不可替代内容。

## 9. 现有仓库的实现前置条件

技术基座已经确定为 Spring AI + PostgreSQL pgvector；具体模型、embedding 方案和外部提供方仍保持可替换。实现前需要先补齐以下稳定边界：

1. 家庭事实的受控只读查询契约，不能直接依赖 `reporting` 或其他模块的 `internal` 类型；
2. `file` 模块向知识处理流程提供安全的内容读取契约，不能直接读取文件卷；
3. 附件上传、恢复、改名、改挂、回收和永久删除的生命周期通知或等价的一致性机制；
4. 知识准备状态、重试和派生数据清理的持久化边界；
5. 家庭事实来源的新鲜度与回答依据格式；
6. pgvector 元数据过滤、向量维度和索引策略的运行约束。

这些能力必须遵守现有 Spring Modulith 模块边界，跨模块只使用公共 API、DTO 和公开领域事件。

这是开发中的项目，计划按当前数据库基线直接增加 pgvector 扩展、知识来源表、派生数据表和索引；不把历史版本兼容、旧数据迁移或升级回滚作为本能力阶段的主要约束。

## 10. AI 能力首期验收基线

首期实现至少应能验证：

1. 活跃成员询问“某物品还有多少、放在哪里”，得到结构化结果、查询时间和家庭事实依据；
2. 两个物品同名时，系统先展示候选，不直接回答错误对象；
3. 成员选定一份可提取文字的物品附件后，可以询问使用或维护步骤并定位到附件内容；
4. 家庭附件、物品附件和批次附件的检索范围符合挂载点规则；
5. 回收附件后立即无法作为依据，恢复后重新准备；
6. 没有有效知识来源时，系统明确说明无法确认，不使用通用知识补答；
7. 家庭事实与知识来源同时使用时，回答分栏标注两类依据；
8. 模型不可用时，家庭事实仍可展示受控查询结果，知识问答不产生无依据回答；
9. 外部提供方只收到最小必要内容，且查询审计不保存问题和回答正文；
10. 备份恢复后，原始附件和知识来源选择保留，派生知识数据可以重新准备。
