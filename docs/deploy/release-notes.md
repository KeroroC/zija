# 知家 v1.0.0 发行说明

**发布日期：** 2026-07-28

知家（zija）首个正式发布版本。一套面向单家庭、多成员的私有部署耐用品与消耗品管理系统，以不可变库存流水为事实来源，覆盖物品全生命周期管理。

## 所含能力（阶段 1-7 摘要）

### 阶段 1-3：基础设施与身份

- **系统模块（system）**：健康检查、安装信息、审计日志查询。
- **身份模块（identity）**：基于会话的认证、用户管理、CSRF 防护、安全 Cookie（生产 profile 强制 Secure）。
- **家庭模块（household）**：家庭引导（bootstrap）、成员管理、邀请链接与兑换、所有者密码恢复。

### 阶段 4-5：物品与位置管理

- **物品目录（catalog）**：物品分类的增删改查，支持耐用品与消耗品区分。
- **位置管理（location）**：存储位置的层级管理，支持归档与禁用。
- **文件模块（file）**：封面图片上传与存储，文件完整性校验端点（OWNER-only）。

### 阶段 6：报表与数据交换

- **库存模块（inventory）**：批次管理、库存位跟踪、六种流水类型（入库/领用/报损/盘点调整/移位/冲正）、库存一致性检查、幂等操作。
- **报表模块（reporting）**：基于投影（Projection）的只读报表，订阅公开领域事件，支持投影重建。包含五张报表视图。
- **全局搜索**：跨物品名/品牌/标签/批次号/序列号/位置名的中文子串匹配。
- **CSV 导出**：按当前筛选或全集导出领域数据，用于数据携带。
- **提醒模块（reminder）**：到期提醒规则配置。

### 阶段 7：发布加固

- **备份与恢复**：运维脚本触发的自包含备份目录（`pg_dump` + 文件卷镜像 + `manifest.json`），恢复时经 REST 端点三连验证（系统信息、文件完整性、库存一致性）。详见 `docs/deploy/backup-restore.md`。
- **结构化日志**：`logback-spring.xml` 文本模式，每条日志含 `requestId` 请求追踪编号。
- **健康端点**：`/actuator/health/liveness` 与 `/actuator/health/readiness` 均可用，`show-details=never` 防泄漏。
- **敏感值防护**：对抗测试断言日志不含密码、会话标识、恢复链接等敏感值。
- **部署文档**：部署指南、备份恢复指南、故障排除指南齐备。

## 明确不做项

以下能力在 v1 中明确不交付，均有对应架构决策记录（ADR）说明理由：

| 不做项 | 理由 | ADR |
|---|---|---|
| 升级冒烟测试 | v1 是首个发布版本，不存在已发布的先前版本可作为升级起点 | ADR-007 |
| 性能验证 | 真实价值在真实规模与硬件下度量，CI 容器化基准不能代表用户体验；伪造规模的性能门只会制造虚假信心 | ADR-008 |
| 应用内备份端点 | 备份由宿主机运维脚本触发，不修改 app 镜像以容纳 `postgresql-client` | ADR-009 |
| CSV 导入 | 阶段六只交付导出，导入需独立设计 |
| 移动端 | v1 为 Web 端，移动端不在范围内 |
| JSON 结构化日志 | 文本模式含稳定字段已满足需求，不增加运维复杂度 |
| 运行时日志脱敏过滤器 | 靠对抗测试 + 代码纪律，不引入运行时开销 |

## 后续路线

- **v1.1**：升级冒烟测试（届时有真正的先前已发布版本可作为起点）。
- **性能验证**：待有真实部署反馈后，按实际硬件与数据规模设计验证方案。
- **CSV 导入**：独立于导出的完整数据导入能力。
- **移动端**：按需规划。
